# Security review — 2026-10-12

Scope: original fork at `ae34789b646d0708edd7d3f4a3863112ad38b76b` (`origin/main`), and this branch's mitigations. Serial source review on the Mac, fake credentials and localhost mocks only. No production access, no real upstream inference, and no real credential-file inspection. Generated fake credentials are used in isolated mock tests. This is a review and qualification candidate, not production approval.

## Authority and access

This is a native Go c-shared library loaded into CPA's process. It has CPA's OS identity, filesystem and network permissions; it is **not sandboxed**. Malicious code or a native/runtime fault can read CPA's credentials, environment and memory, alter requests, or kill the whole proxy. A dedicated adapter user does not isolate the plugin itself.

The registered capability is only `request_normalizer`. CPA 8.0.26 supplies `FromFormat`, `ToFormat`, `Model`, `Stream`, and `Body` (raw translated request bytes, JSON/base64 in the RPC envelope). **No headers, chosen auth record, upstream keys or separate session identity are supplied by this capability.** Bodies can contain client identity fields: the native path hashes `prompt_cache_key` for session separation. The normalizer can replace the body, including every message, tool description and attachment represented there. This implementation reads typed user text and previous assistant text, and inserts effort directives only on allowed model prefixes. It does not call host APIs, inspect auth files, enumerate credentials, or change headers or scheduling. The C init host callback table is checked for ABI compatibility but never retained or used.

## Exact prompt disclosure and network behavior

For each eligible new typed user turn it sends one POST to configured `jev-url`, default `http://127.0.0.1:8765/v1/systemone`:

- `model`: configured `jev-model`, default `jev-latest`.
- `state.user_message`: first **1200 Unicode runes** of extracted user text; string content is taken verbatim; text/input_text blocks are joined with newline.
- `state.assistant_previous_reply_tail`: last **600 Unicode runes** of text/output_text from the most recent preceding assistant message; string assistant content is included.
- `state.router_shadow`: explicit plugin shadow-mode boolean; local gateway requires it for comparison.
- `state.turn_id`: SHA-256 identity of version, requested model, previous assistant tail, and a chained digest of typed user history. Added on this branch for stable adapter sessions.
- `questions.effort`: fixed choice instructions and low/medium/high/xhigh descriptions in `router.go`.

A text block or whole string **starting exactly** with `<system-reminder>` is excluded. This does not scrub embedded reminders, whitespace-prefixed reminders, pasted files, secrets typed by the user, or secrets reproduced by the assistant. Image/audio blocks, tool-use input and tool results are not sent; a user message containing a `tool_result` block is skipped entirely. System instructions and full conversation history are not sent. Hashing uses full typed text locally, not just the truncated portion.

Only Content-Type and the optional **configured classifier key** are set. Client/upstream Authorization and session headers are not copied. Arbitrary HTTP/HTTPS classifier origins remain configurable: choosing a remote endpoint discloses the above prompt content to it. For the reference deployment, use the loopback adapter. The new transport ignores environment proxies, refuses redirects, caps the classifier response at 16 KiB, requires valid JSON and an allowed effort, and logs only fixed error categories/status numbers. This prevents response/error echo and redirect exfiltration; it does not restrict an administrator's chosen remote classifier URL.

The local gateway defaults to actual Zen Jev, POST `https://opencode.ai/zen/v1/systemone`, with its protected Zen key and fixed effort rubric. It sends only the two truncated text fields; turn IDs/shadow metadata stay local. Production Jev egress is pinned to that exact HTTPS endpoint; literal loopback HTTP endpoints are allowed for mocks/local Jev. Redirects and environment proxies are rejected. Jev responses are capped at 16 KiB and choice values validated; raw response/probability/error fields are never returned or logged.

Optional `-compare-ocg` makes a second call concurrently through loopback CPA, using a separate dedicated CPA key, opaque per-turn X-Opencode-Session, fixed identical rubric, strict schema, low reasoning, max_output_tokens=256, stream=false/store=false. Thus the same 1200+600-rune prompt state goes to **both** Zen/TypeSafe and OCG in comparison mode. It is allowed only with explicit `state.router_shadow:true`; active requests fail before either call. Logs record both observations/latencies/outcomes and agreement only on dual success. DeepSeek never replaces Jev's choice. Each paired turn is joined under one deadline; four turns/eight upstream calls maximum. Request bodies are capped at 16 KiB; CPA responses at 64 KiB. Jev-only reads no CPA credential and requires no new CPA access key. Usage missing from Jev is explicitly unavailable, not zero cost. `store:false` is a preference to the OCG backend, not a retention guarantee.

The listener remains loopback-only, but outbound HTTPS/DNS is required for Zen; the former loopback-only systemd IP filter is removed. Any local process able to reach the gateway can consume classifier usage. Caller-supplied shadow markers are not authentication. Ordinary credential access is restricted to service/root, but an operator account with sudo can still read it: host policy, not file mode, is the effective secret-read boundary. `/etc/jev-ocg-adapter/zen-key` must be added to guard coverage before provisioning; existing runtime wildcard covers it. A comparison-mode CPA key grants every CPA upstream/model, not only `ocg/*`; mitigations are loopback CPA transport, LoadCredential, guard discipline and independent rotation, not model scoping. Pure Jev avoids this extra unscoped key.

## State, privacy and consistency

Default path remains `$HOME/.cli-proxy-api/effort-router.jsonl` **inside CPA's environment**. Tilde strings in YAML are not expanded; an absolute path is required. Deployment uses `/var/lib/cliproxyapi/effort-router/shadow.jsonl`, in a private CPA-owned 0700 directory. New files are 0600; nonregular files, final-component symlinks, and group/world-accessible files are refused on Linux/macOS/FreeBSD. Protect parent directories too; the plugin cannot defend against its own privileged UID or compromised root.

Each line contains SHA-256 key, effort (or `-`), optional UTC timestamp, **configured model prefix**, latency ms, `shadow:true` when applicable, and fixed error category. It contains no preview/prompt, classifier response, URL or key. Hashes are not anonymous: known inputs can be guessed/correlated offline. Older logs may already contain `preview` and echoed error text; this branch does not erase them. Quarantine those separately with operator handling.

Writes are append-only under a per-state mutex, checked and fsynced **before** a decision becomes applicable. A write/read error stops new decisions until restart/reconfiguration to a fresh file; already known decisions remain stable. If an append reached disk but fsync/close fails, a complete tentative record may remain. After any state error, retire the suspect file and use fresh sessions/a fresh file; a restart alone cannot certify its consistency. Blank lines and a torn final JSON record are tolerated. No automatic rotation/compaction/retention limit exists. Disk and the in-memory map grow linearly in distinct turn identities, including failed and pre-router turns; size depends on model prefix/error fields (typically hundreds of bytes per classification). Plan storage and observe growth. Never truncate an active decision file while sessions still reference it. A single CPA process/library must own each file; there is no cross-process file lock. Configuration swaps publish a consistent config/state pair and network calls hold no state/config lock. Same-key concurrent requests wait for one decision. At most eight classifier calls run concurrently; excess new keys become permanently uninjected for that turn.

Shadow records have separate in-memory and reload namespaces. They cannot become active inserts. Existing pre-router turns are recorded as `-` in active mode. Use a **new active state file and fresh client sessions** when enabling. Old 24-character text-only keys are deliberately not migrated to the new identity format. Identical Claude typed history/model/assistant tail across separate sessions still shares a decision; native requests include the body cache key and compaction epoch in their identity. History edits, different model names or changing the assistant tail can change a digest and suppress historical inserts. Claude compaction lacks the native opaque-anchor reset. These are remaining cache/qualification limitations.

## Findings and disposition

| Severity | Original issue | This branch / remaining condition |
| --- | --- | --- |
| High | Persisted 80-rune user previews and classifier response/error text could contain prompts or secrets. | Removed previews and raw error text; only bounded constructed log fields remain. Existing historical logs require operator handling. |
| High | Global mutex held during classifier HTTP call: traffic serialized; CPA loopback re-entry could deadlock before checking model eligibility. | Separate config/state locks, network outside locks, per-key deduplication, eight-call cap; `ocg/` routing prefixes rejected. Recursive mock test covers it. Planned list is Claude/GPT-6.1-Sol only. |
| High | Unbounded classifier response allocation in the credential-bearing process; unguarded plugin panic could escape Go/C boundary. | Bounded response, ABI request length cap (64 MiB RPC envelope, before C.int conversion), ABI version/pointer checks and panic recovery. Fatal runtime/OOM/C memory faults remain whole-process failures. |
| Medium | Redirects/proxy environment could send prompt data to another endpoint; echoed errors could disclose URL credentials. | No redirects/environment proxies; URL userinfo/query rejected; generic errors. Chosen remote HTTP endpoints are still trusted admin configuration. |
| Medium | Text-only decision key shared unrelated turns/models; state failures still applied undurable inserts; symlinks/permissive files accepted. | Full digest of model/context/chained typed history, plus native body cache key/epoch; persistence before apply; private regular nofollow state files. Claude session separation and interprocess locking remain absent. |
| Medium | Configuration parse errors ignored; zero/negative timeout disabled a useful deadline. | Reject malformed YAML/invalid settings without replacing current config; timeout range 1..30000 ms. |
| Medium | No shadow mode; qualification required changing upstream request bodies. | `shadow:true` classifies/persists while returning byte-identical bodies; shadow namespace isolated from active replay. Default false preserves original behavior; deployment explicitly true. |
| Low | Claude normalization could duplicate a preceding router directive; top-level explicit effort wasn't preserved. | Repeated normalize pass skips existing empty effort-only directive; top-level nonbaseline Claude effort wins. |

No evidence of intentional credential collection was found in this source. This does not certify CPA, dependencies, classifier correctness, upstream caching, or the installed binary.

## Native Codex candidate and evidence

Native Responses sampling now routes only when CPA targets `codex`; standalone compact targets `openai-response` and remains byte-identical. Native baseline defaults high (`codex-baseline-effort`), separate from Claude medium; no top-level reasoning rewrite occurs. Existing nonbaseline client settings/updates win. Baseline update items directly before/after the user are replayed with the chosen effort in the existing slot to avoid adjacent updates. Native keys include hashed prompt_cache_key and compaction epoch; only the latest eligible typed user message can be newly classified. Historical/compaction turns cannot be classified late. Opaque compaction anchors reset scope and block obsolete inserts before that anchor. Streamed compaction_trigger requests replay known updates without making new decisions. Automatic context_management/truncation stays untouched.

New optional `proof-file` (disabled by default) writes only whitelisted item/role/effort shapes, `[REDACTED]` payload markers, an ephemeral HMAC scope, and equality results for request/top fields and history prefixes. The random key is memory-only and never persisted. Formats/models are bounded/whitelisted. Maximum 4096 items per observation and 128 remembered diagnostic scopes; eviction resets comparison, never claims a prior match. Diagnostic storage is append-only/0600/non-symlink regular-file-only, with no rotation; errors produce missing evidence and must block a proof claim, not change routing. This observes the **normalizer stage**, not a remote effort acknowledgement or cache hit.

Public Codex source is pinned to rust-v0.162.1 / `092d3acd6bec3e3a14bdc7e7a2810ab628ab759d`; synthetic shapes and references are in `testdata/codex-0.162.1/`. The official CPA 8.0.26 darwin/aarch64 archive was checksum verified (`525040a0c901a4e6174ba604b852b96de111b54be5325942a99c00c2c4593b36`) and run with an empty auth dir, allowlisted child environment and only local mock upstreams. `scripts/cpa-mock-proof.py` passes disabled-baseline/shadow/active sampling, tool replay, both compact paths, fresh-window effort and Claude regression. Redacted mock receipts are [CODEX-MOCK-EVIDENCE.json](CODEX-MOCK-EVIDENCE.json); all simulated cache numbers are **not live cache evidence**. Real OpenAI acceptance, native CLI/IDE execution and caching remain unproven. Production installation should wait until the approved live proof passes. Mac/darwin builds are test scaffolding only.

Mac proof credentials/private logs are operator-created under `~/Library/Application Support/effort-router-proof/private/` (0700 dirs/0600 files). Repo `.claude/settings.json` denies Read/Edit/Grep on that prefix; Codex sessions must never read/edit/search it, including through cat/grep/head/jq or scripts. These rules and same-UID file permissions are discipline/defence-in-depth, not complete OS isolation. Only normal CPA/adapter processes invoked by the operator use the credential paths; only HMAC-redacted evidence leaves the prefix. Cleanup/revocation is the operator's step in the proof plan.
